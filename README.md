# B Your Wealth 1 — Living Benefits Survey V2.0

ระบบ Web App (ต้นแบบสำหรับทดสอบภายใน) ที่ต่อยอดแบบสำรวจ Living Benefits จากแบบฟอร์ม 5 ขั้นตอน มี **Dashboard / ฐานข้อมูลลูกค้า / ที่ปรึกษากรอก / ส่งลิงก์ให้ลูกค้ากรอกเอง / รายงาน / SQLite** และไม่ใช้แพ็กเกจภายนอก

> **สำคัญมาก**: ระบบนี้เป็น *functional local prototype* มิใช่ระบบ production-ready สำหรับข้อมูลสุขภาพลูกค้าจริง เพราะยังไม่มีประกาศความเป็นส่วนตัวและผู้ควบคุมข้อมูลที่ตรวจสอบแล้ว, การเข้ารหัสฐานข้อมูล, ระบบจัดการสิทธิ์องค์กร, 2FA, การตรวจสอบความปลอดภัย, ระบบสำรองข้อมูลเข้ารหัส, ระบบกำหนด retention / audit log / คำขอสิทธิเจ้าของข้อมูล และมาตรการคุ้มครองข้อมูลตาม PDPA ครบถ้วน

## 1. วิธีติดตั้งและเปิดใช้งาน (Mac / Windows / Linux)

ต้องมี **Python 3.10 ขึ้นไป** และไม่ต้อง `pip install` เพิ่ม

1. แตก ZIP ลงเครื่อง
2. เปิด Terminal และไปยังโฟลเดอร์โปรเจกต์ เช่น `cd ~/Downloads/Living_Benefits_Survey_V2`
3. เริ่มตั้งค่าผู้ดูแลระบบเพียงครั้งแรก:

   ```bash
   python3 server.py setup
   ```

   ตั้งชื่อผู้ใช้และรหัสผ่านที่ยาว **อย่างน้อย 12 ตัวอักษร** ระบบเก็บรหัสผ่านในรูป PBKDF2-HMAC-SHA256 พร้อม salt ไม่เก็บรหัสผ่านจริง

4. เริ่มเซิร์ฟเวอร์:

   ```bash
   python3 server.py
   ```

5. เปิดเบราว์เซอร์ในเครื่องที่ **http://127.0.0.1:8787** แล้วล็อกอิน

6. ปิดระบบโดยกด `Ctrl+C` ใน Terminal

หาก Windows ใช้ Python launcher: `py server.py setup` และ `py server.py`

## 2. การทำงาน

- **Dashboard**: จำนวนลูกค้า แบบสำรวจที่ส่งแล้ว/รอตอบ และยอดช่องว่างความคุ้มครองรวมจากผลที่ส่งแล้ว
- **ฐานข้อมูลลูกค้า**: เพิ่ม/แก้ไข/ลบลูกค้า, เบอร์โทร, บันทึกข้อความ, ดูจำนวนแบบสำรวจของลูกค้า
- **สำหรับที่ปรึกษา**: สร้างลูกค้า → เลือก “ที่ปรึกษากรอกให้” → เปิดลิงก์แบบสำรวจ
- **สำหรับลูกค้า**: สร้างลูกค้า → เลือก “ลูกค้ากรอกเอง” → คัดลอกลิงก์ส่งให้ลูกค้า (ลิงก์เปิดแบบสอบถามโดยไม่ต้องล็อกอิน)
- **แบบสอบถาม**: 5 ขั้นตอน เหมือน V1 โดยบังคับรับความยินยอมก่อนกรอก และส่งเข้าฐานข้อมูล **เฉพาะเมื่อกดส่งผลสำรวจ**
- **ลิงก์**: สร้าง token แบบสุ่ม 256-bit, เก็บ hash ในฐานข้อมูล, หมดอายุ 7 วัน, ใช้ได้ 1 ครั้ง, ต่ออายุโดยสร้างลิงก์ใหม่ (ลิงก์เดิมใช้ไม่ได้ทันที), สามารถยกเลิกได้
- **รายงาน**: เมื่อส่งแล้ว ที่ปรึกษาเปิดดูคำตอบอย่างละเอียด คำนวณค่าใช้จ่าย A/B/C, พิมพ์/PDF, ส่งออก JSON ต่อรายการ
- **ฐานข้อมูล SQLite**: อยู่ใน `data/living_benefits.sqlite3` (โฟลเดอร์ `data/` สร้างอัตโนมัติเมื่อ setup)

**หมายเหตุเกี่ยวกับการส่งลิงก์:** ค่าเริ่มต้น `127.0.0.1` เป็นเซิร์ฟเวอร์ส่วนตัวในเครื่อง ไม่ใช่เว็บไซต์สาธารณะ ลูกค้าบนมือถือ/ภายนอกบ้านยังเข้าถึงลิงก์นี้ไม่ได้ ต้องติดตั้งบนโฮสต์ HTTPS จริงและตั้งค่าโดเมน/Reverse Proxy ที่ปลอดภัยก่อน จึงจะส่งลิงก์ข้ามอุปกรณ์ได้ โหมดกรอกให้ลูกค้าใช้ได้ทันทีบนเครื่องเดียวกัน

## 3. สูตรประเมิน

- ค่าใช้จ่ายจำเป็น/เดือน = บ้าน + รถ + อุปโภคบริโภค + ค่าเทอม × จำนวนเทอม/12 + เลี้ยงดูบุพการี + เดินทาง + อื่น ๆ
- A = ค่าใช้จ่ายจำเป็น/เดือน × 12 × จำนวนปีสำรอง หรือจำนวนเงินที่กำหนดเอง
- B = เงินก้อน CI เจอจ่ายจบ + ผลประโยชน์ CI แบบจ่ายซ้ำ **สำหรับการจ่ายครั้งแรกเท่านั้น**
- C = `max(A − B, 0)`
- ไม่บวกยอดหนี้คงเหลือ, ค่าชดเชยรายวัน หรือการจ่ายซ้ำในอนาคตเป็นเงินก้อนอัตโนมัติ
- เซิร์ฟเวอร์คำนวณตัวเลขใหม่ทุกครั้ง **ไม่เชื่อผลคำนวณที่ส่งจากเบราว์เซอร์**

## 4. ข้อจำกัดด้านความปลอดภัยและ PDPA ก่อนใช้จริง

เนื่องจากคำตอบเรื่องโรคและพฤติกรรมเป็นข้อมูลส่วนบุคคลอ่อนไหว ผู้ควบคุมข้อมูลต้องจัดการอย่างน้อยดังต่อไปนี้ก่อนนำไปใช้งานกับลูกค้าจริง:

1. ระบุผู้ควบคุมข้อมูล/เจ้าหน้าที่คุ้มครองข้อมูล (ถ้ามี), ประกาศความเป็นส่วนตัว, วัตถุประสงค์, ฐานกฎหมาย, ขอบเขตการเปิดเผย, ระยะเวลาเก็บรักษา, ช่องทางใช้สิทธิ และข้อความขอ **ความยินยอมโดยชัดแจ้ง** ที่ผ่านการตรวจสอบแล้ว
2. ใช้ HTTPS เท่านั้น และกำหนด `SURVEY_SECURE_COOKIES=1` สำหรับระบบ production หลัง Reverse Proxy ที่มี TLS
3. เข้ารหัสข้อมูลที่จัดเก็บ (*encryption at rest*), เข้ารหัส backup, จัดเก็บกุญแจแยกจากเซิร์ฟเวอร์ฐานข้อมูล
4. เพิ่มระบบจัดการผู้ใช้งานหลายคน, RBAC แยกที่ปรึกษาตามลูกค้า, MFA, rate limiting ระดับ IP, audit log การอ่าน/แก้ไขข้อมูล, การแจ้งเหตุข้อมูลรั่ว, และการตรวจสอบโดยผู้เชี่ยวชาญ
5. เพิ่มระบบลบข้อมูลตามกำหนดและขั้นตอนถอนความยินยอม/ลบข้อมูลทุกสำเนา รวมถึง backup และ export JSON
6. **อย่าอัปโหลดไฟล์ `data/*.sqlite3` หรือ JSON ที่มีข้อมูลลูกค้าขึ้น GitHub** (`.gitignore` มีให้แต่ต้องระมัดระวัง)
7. การกรอกโดยที่ปรึกษาต้องมีหลักฐาน/อำนาจที่ถูกต้องในการให้ความยินยอมจากเจ้าของข้อมูล ไม่ควรให้ที่ปรึกษากดแทนโดยไม่มีอำนาจ
8. ลิงก์แบบสำรวจเป็น bearer link ผู้ที่มีลิงก์สามารถส่งคำตอบในนามรายการนั้นได้ ต้องส่งทางช่องทางปลอดภัยและยืนยันตัวผู้ตอบตามระดับความเสี่ยงที่เหมาะสม; ต้นแบบยังไม่มี OTP/ยืนยันตัวตนลูกค้า
9. SQLite เหมาะกับการสาธิตและโหลดขนาดเล็ก ยังไม่มีระบบแยก tenant / HA / encrypted backups
